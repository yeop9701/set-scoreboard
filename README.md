# 세트 스코어보드

세트마다 체크해서 채우는 2인용 운동 기록 앱. 의존성 없는 단일 페이지이고,
빌드에 필요한 것은 Node뿐이다.

- 세트별 체크 핍(`●●●○○○○`)이 곧 체크박스이자 진행바
- 남은 세트와 남은 횟수를 항상 큰 숫자로 표시
- 러닝처럼 세트가 없는 종목은 거리/시간 입력 또는 GPS 측정
- 연속 완주 스트릭, 월별 밀도 히트맵, 주간/월간 달성률
- 세트 완료 시각 타임스탬프 기록, CSV/JSON 내보내기
- 자정이 지나면 하루가 마감되고 못 채운 세트는 "실패"로 남음
- 사람마다 목표와 기록이 분리되고, 오늘 화면에서 서로의 진행을 확인

## 저장소는 실행 환경에 따라 정해진다

앱은 열린 환경을 보고 저장소를 스스로 고른다. **어디로 열었는지에 따라 공유
여부가 달라지므로** 아래를 알고 써야 한다. 설정 탭 맨 위 배지에 지금 어느
모드인지 항상 표시된다.

| 모드 | 조건 | 두 사람 공유 | 기기 간 동기화 |
|---|---|---|---|
| `supa` 공유 저장 | 아래 Supabase 설정을 마친 웹 주소 | **○** | **○** |
| `cloud` 서버 저장 | Claude 아티팩트 뷰어 안 | ○ (같은 조직만) | ○ |
| `local` 이 기기에만 | 설정 전 웹 주소, 로컬 파일 | ✗ | ✗ |
| `memory` 저장 안 됨 | 브라우저가 저장을 차단 | ✗ | ✗ |

`cloud`는 claude.ai 뷰어가 페이지에 주입하는 `window.claude` 런타임 기능이다.
일반 웹 주소에는 그 객체가 없다. 반대로 아티팩트는 CSP가 외부 통신을 막아
Supabase에 접근할 수 없다. **그래서 두 저장소는 서로 이어지지 않는다.**
하나를 골라 쓰고, 옮길 때는 설정 → JSON 백업 → 가져오기를 쓴다.

## 기록 공유 붙이기 (Supabase)

GitHub Pages는 정적 파일만 서빙하므로 그 자체로는 두 사람의 기록을 이어줄 수
없다. 무료 등급 Supabase를 저장소로 붙이면 주소 하나로 공유된다. 준비는 한
번이면 끝난다.

1. supabase.com 가입 → New project (지역은 Northeast Asia (Seoul) 권장)
2. SQL Editor 에 `supabase-setup.sql` 전체를 붙여넣고 Run
3. Project Settings → API 에서 두 값을 복사해 `workout.html` 상단의
   `SUPABASE_URL` 과 `SUPABASE_ANON_KEY` 에 넣는다.
   **anon public 키를 쓴다. service_role 키는 절대 넣지 말 것** — 그건 모든
   권한을 가진 비밀키라 공개 저장소에 들어가면 안 된다.
4. `node build.js` 로 다시 빌드하고 커밋·푸시

### 방 코드와 초대 링크

로그인이 없으므로 "누가 같은 기록을 보는가"는 **방 코드**로 정한다.

- 앱을 처음 열면 128비트 난수 방 코드가 만들어지고 주소에 `#r=...` 로 붙는다.
- 설정 → 저장 위치 카드의 **초대 링크**를 같이 운동하는 사람에게 보낸다.
  그 링크를 연 사람은 같은 기록을 함께 쓴다.
- 방 코드는 저장소에 커밋되지 않는다. anon 키가 공개돼도 방 코드를 모르면 아무
  기록도 읽을 수 없다. `entries` 테이블은 RLS로 직접 접근이 전면 차단돼 있고,
  유일한 통로인 `security definer` 함수 세 개가 방 코드를 인자로 요구한다.
- **두 번째 기기에서는 반드시 초대 링크로 열 것.** 맨 주소로 열면 새 방이
  만들어져 빈 기록으로 시작한다. 그 경우 프로필 선택 화면이나 설정 → 저장 위치
  에서 방 코드를 직접 입력하면 원래 방으로 돌아간다.

공유 저장소에는 실시간 푸시가 없으므로 20초마다, 그리고 앱으로 돌아올 때마다
상대방의 변경을 끌어온다.

## 파일 구성

```
workout.html            앱 본체. 여기만 고치면 된다.
supabase-setup.sql      Supabase 준비용 SQL (한 번만 실행)
build.js                배포본 생성기
index.html              (생성) workout.html에 doctype·viewport·PWA를 씌운 것
manifest.webmanifest    (생성) PWA 매니페스트
sw.js                   (생성) 오프라인 캐시용 서비스워커
icons/*.png             (생성) 앱 아이콘
.nojekyll               Pages의 Jekyll 처리 비활성화
```

`workout.html`에는 `<!doctype>`·`<head>`·`<body>`가 없다. 아티팩트로 발행할 때는
claude.ai가 그 껍데기를 붙여 주기 때문이다. 그래서 일반 웹에 올리려면 반드시
`build.js`를 거쳐야 한다. 특히 viewport 메타가 없으면 휴대폰에서 데스크톱 폭으로
렌더링되어 화면이 깨진다.

## 빌드

```
node build.js
```

`workout.html`을 고칠 때마다 실행한다. 생성물도 저장소에 커밋한다 — GitHub
Pages는 빌드 단계 없이 커밋된 파일을 그대로 서빙하기 때문이다.

## 배포

### GitHub Pages

저장소 Settings → Pages → Source를 `Deploy from a branch`, 브랜치를 `main` /
루트(`/`)로 지정한다. 푸시하면 1~2분 안에 반영된다.

### Claude 아티팩트

`workout.html`을 Artifact로 발행한다. 서버 저장과 파일 저장을 쓰므로
`db`, `downloads` 두 기능을 선언해야 한다.

## 휴대폰에서 쓰기

1. Pages 주소(또는 받은 초대 링크)를 연다.
2. 아이폰은 공유 → 홈 화면에 추가, 안드로이드는 메뉴 → 앱 설치.
3. 프로필을 고르면 주소에 `#p=...` 가 붙는다. 그 상태로 홈 화면에 추가하면
   바로가기마다 다른 사람으로 열린다.

알림은 페이지(또는 설치된 앱)가 열려 있을 때만 울린다. 브라우저는 닫힌 페이지에
예약 알림을 보낼 수 없다.
